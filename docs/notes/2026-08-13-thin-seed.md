# 2026-08-13 — Two-widget / thinner seed

Non-authoritative (see [`README.md`](README.md)). Catalogue:
[`../engineering/making-it-fit.md`](../engineering/making-it-fit.md).
Prior: [`2026-08-13-entities-only-check.md`](2026-08-13-entities-only-check.md).

**Status:** local done; **not adopted as a cap solution**.

**Hypothesis:** The starter is too fat. The entities page is 281 MB because it
pulls eight Base UI widgets (and AppShell's sidebar/menu/avatar). Keep button
and input real; stub the other Base UI wrappers so they do not import
`@base-ui/react`. Union and page heap then sit nearer the isolate cap.

## How to re-run

From the monorepo root, after `pnpm install` and
`pnpm --filter @sfab-lite/kernel install-universe`:

```bash
NODE_OPTIONS=--max-old-space-size=8192 pnpm --filter @sfab-lite/check measure:thin-seed
```

Harness: `apps/check/scripts/measure-thin-seed.ts`. Overlays
`avatar`, `badge`, `dropdown-menu`, `sheet`, `sidebar`, and `tooltip` with
DOM-null stubs. `button.tsx` and `input.tsx` stay as in the seed.

## Verdict

**Starter fatness is real and not the cap.** Shipping fewer Base UI widgets
would recover the historical 22-file load and tens of megabytes. It does not
put a UI route, or the union, under the isolate. React / the remaining widget
graph / the rest of the app still dominate. Do not treat "delete sidebar" as
the memory architecture.

## Does not imply

- That `@base-ui/react` should stop shipping whole in the VFS — the exception
  is still load-bearing for capability; this only changes how much of it a
  *thin template* loads.
- That stacking with shallow RPC was measured here.

## Follow-ups

- A thinner default shell is a product choice, not a check-cap fix.
- Stacking two-widget + shallow RPC on the entities page was not run.
