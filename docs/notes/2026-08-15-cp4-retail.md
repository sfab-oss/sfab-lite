## Verdict — checkpoint 4

**The units architecture still holds after the starter rebuild: 0/8
OOM, same as checkpoint 3 and the union baseline.** The before/after
pair is clean: same protocol, same org, same n, recipes now inside
the checked seed.

Costs, named, against checkpoint 3 (units, unused-recipe copies) and
the union baseline:

- **Wall per check is not worse, and in this sample is cheaper.**
  This run 12.7–13.9 s (one 20.9 s outlier) vs checkpoint 3's
  17.0–19.5 s (one 45.6 s) vs the union's 10.6–13.3 s. Create-to-ready
  88–92 s (one 104 s) vs checkpoint 3's 117–125 s (one 178 s) vs the
  union's ~94–100 s. A walkthrough create the same morning was 89 s
  ready, same shape.
- Local product-path heaps for this seed (server **243.2** / emit
  **248.4** / client **318.6** MB) still sit well above 128 MB and
  still did not stop the isolate — same lesson as checkpoint 3.
  Client heap is down from the PR 7 unused-copy tree (371.5 MB);
  that is the only local movement that lines up with a cheaper
  live wall, and it is not a mapping we will lean on.

## Does not imply

- That the true OOM rate is zero — n=8; the 95% upper bound is
  roughly 30%, exactly as it was for checkpoint 3 and the baseline.
- That the 20.9 s outlier is understood. One occurrence, same
  cold-isolate guess as the 45.6 s at checkpoint 3; smaller this
  time, still not a series.
- That local Node heap now predicts isolate wall. Client 371 → 319 MB
  and wall 17 → 13 s happened in the same PR; that is a coincidence
  until someone measures it on purpose.
- Permission to skip the next re-tail when the checked surface grows
  again (image v0 is the named candidate).
